5 / Making the limit part of the object

A construction can run out of room #

Finite memory alone does not guarantee termination: a machine can revisit a state and loop. A finite step budget bounds an attempt. Every larger budget is another finite allowance, not permission to finish infinitely many steps.

Design proposal 5.1 · Bounded construction. A construction consumes explicit state and resources, returning either a value with new state, a rejection, or resource exhaustion.

construct(input, state, budget)
  → ok(value, newState, remainingBudget)
  | rejected(reason)
  | exhausted(resource)

A type specifies valid representations and evidence. A constructor may try to produce an inhabitant; a checker may try to validate one. The constructor’s inability to finish does not show that the type has no inhabitants.

The allocator below is implemented. The general type-and-effect notation is a proposal, not yet a language or a verified typing calculus.

For a set-like collection we must additionally define equality, membership, and duplicate handling. For a stateful reference we must specify which snapshot it describes. A changing container and a mathematical set are different objects; one does not define the other automatically.
